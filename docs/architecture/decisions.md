# Decisions

| Date | Decision | Why |
|---|---|---|
| 2026-11-17 | Build new on libraries, no fork (D1 = A) | Complete open tools are tiny or stale; healthy ones are tied to one stack. |
| 2026-11-17 | Python core, Next.js panel (D2 = A) | Audio pieces (faster-whisper, jiwer, VAD) live in Python. |
| 2026-11-17 | Demo and panel first, real agents in phase 3 (D3 = B) | Owner choice. |
| 2026-11-17 | License Apache-2.0 (D4 = A) | Patent grant; matches most dependencies. |
| 2026-11-17 | Name PanchoVoiceAI, companion Panchito (D5 = A) | Owner choice. Trademark and domain not checked yet. |
| 2026-11-17 | Repo private until phase 2 ends (D6 = A) | Owner choice. |
| 2026-11-18 | Repo made public after phase 2 | Owner approved. |
| 2026-11-18 | Default LLM provider is `claude-cli` (the `claude -p` command on the owner's subscription); `anthropic` API key and `ollama` are alternatives | Owner asked to use the subscription when possible. No API key is configured on the build PC. |
| 2026-11-18 | Demo agent is a small custom Python WebSocket agent (faster-whisper + Ollama + Kokoro), not Pipecat | Fewer moving parts for a demo that must run with one command; Pipecat stays the planned base for the live caller and platform adapters in later phases. |
| 2026-11-18 | Scenario keys are English | Public open source tool; docs get a Spanish quick start. |
| 2026-11-18 | VAD from faster-whisper's bundled Silero ONNX model, no torch | Avoids a large torch install; same model. |
| 2026-11-18 | TTS through an OpenAI compatible Kokoro HTTP server (kokoro-fastapi), Docker image in compose | Already the common way to run Kokoro locally; no Python TTS deps in core. |
| 2026-11-18 | Panel is a Next.js static export served by the core server | One process and one port for users; the wizard stays simple. |
| 2026-11-18 | Panel uses `trailingSlash: true`: every page is `out/<path>/index.html`; detail pages take the id in the query (`/runs/view/?id=`) | Static export has no runtime routes. Folder plus index.html works on any static server, including the core server. |
| 2026-11-18 | Panel build copies Next 16 prefetch files to flat names (`web/scripts/flatten-segments.mjs`) | Next 16 writes them in nested folders but the browser asks for dotted names, so a plain static server answers 404 on every link prefetch. |
| 2026-11-18 | `GET /api/fixtures` list shape is open in the contract; the panel accepts a list of ids (strings) or objects `{id, description?, file?}`. `GET /api/fixtures/{id}` `json` may be an object or a JSON string. `PUT` sends `{json: <object>}` | Closest reading of section 7; the panel stays working with either server choice. |
| 2026-11-18 | Panel falls back to local demo data when `GET /api/health` fails or takes over 1.5 s, or with `?mock=1` / `NEXT_PUBLIC_MOCK=1`; a "Demo data" badge shows it | The panel must work before the core server exists, and a first visit with the server down should still show something useful. |
| 2026-11-18 | Onboarding step text and actions live in the panel (`web/lib/onboarding.ts`); the server only stores `{id, title, done}` | Keeps the API small. `agent_added` and `ci_enabled` have an "I did this" button that POSTs the step, because the panel cannot detect them. |
| 2026-11-18 | Demo agent extras outside pv-ws/1: plain HTTP `GET /health` on port 8710 answers `ok` (any other non `/ws` path is 404); the agent sends `tool_call` messages for every tool it runs; it ignores audio frames that arrive before `start` | `/health` gives core and the wizard a cheap reachability check without opening a call. Nothing in section 5 changes. |
| 2026-11-18 | Demo agent binds to `127.0.0.1` by default (`ACME_HOST=0.0.0.0` in Docker) and uses whisper `base` as the default STT model; `--stt-model small` is the accurate option | Measured p50 voice to voice on the build PC: 2.0 s with `base`, 4.1 s with `small`. With `base` the first demo run fails on the planted bug, not on latency. |
| 2026-11-18 | Demo agent with the bug off enforces the confirmation in code: `book_appointment` runs only after a question naming the same day and time and a caller yes; otherwise the model gets `{"ok": false, "error": "confirm_first", ...}` and the mock is not called. Bug on is unchanged | With the prompt alone, qwen2.5:7b passed confirm-before-booking 2 of 3 runs; the demo story needs "turn the fix on, it passes". |
| 2026-11-18 | Demo agent claim guard: a sentence claiming a booking or cancellation is not spoken unless `book_appointment` / `cancel_appointment` succeeded in the same turn; the model is asked again once, then a safe fallback line is spoken | Core runs found the agent saying "you are booked" with no tool call, a second failure that made the demo noisy. The planted bug (book without read back) is unchanged. |
| 2026-11-18 | Core: scenario turns get an optional `pause_ms` (extra silence before the caller speaks that turn) | Needed for the long-silence scenario. Optional and additive, so every v1 file stays valid. |
| 2026-11-18 | Core: `llm.url` is an optional key in `panchovoice.yaml` (base url for `ollama`, default `http://localhost:11434`) | Section 1 has no place for it. Optional and additive. |
| 2026-11-18 | Core: every check has `status` (`passed`, `failed`, `error`) next to `passed` (true, false, or null for error). A run is `failed` if any check failed, else `error` if any check could not be measured (judge down, no user transcript for `wer_max`, barge-in not exercised), else `passed` | Section 6 says judge errors are `error`, not failed. The same rule fits other checks the harness cannot measure. Errors stay out of the pass rate and fail the gate, per section 8. |
| 2026-11-18 | Core: implicit checks `agent_replied` (at least one spoken reply) and `call_completed` (fails when the agent drops the socket without `end`) | Facts first: a silent or crashing agent must fail even when a scenario lists few expectations. |
| 2026-11-18 | Core: `final_state` with an empty list (for example `appointments: []`) means the collection must be empty | A subset match against an empty list would always pass and be useless for "must not book" scenarios. |
| 2026-11-18 | Core: `mock_tools_url` uses `http://127.0.0.1:<port>/mock/<session>`, not `localhost`. `pv run` serves the mock router itself on 8700; if 8700 is busy it uses a free port (the url in `start` tells the agent) | On Windows a client that tries `::1` first can wait about 2 s per request, which would show up as agent latency. Sessions live in the process that runs the call, so a `pv run` next to a running `pv serve` needs its own port. The server can mount the same `make_mock_router(registry)` and pass `mock_base_url`. |
| 2026-11-18 | Core: run results add keys `risk`, `title`, `language`, `mode`, `notes`, `ended_by`, and `cost.provider`; `transcript.json` is `{lines: [{t_ms, role, text, source}], events: [agent messages with t_ms], ended_by, duration_ms}` | Extra keys only; the panel and the gate need risk and the reason a call ended. |
| 2026-11-18 | Core: `pv run --agent A` filters scenarios to agent A (it does not retarget them) | Scenarios are tied to fixtures and agent behavior; retargeting can come later as an explicit flag. |
| 2026-11-18 | Core: suite ids are `s_YYYYMMDD_HHMMSS` with a `_2`, `_3` suffix on a clash in the same second | Two suites in one second would collide. |
| 2026-11-18 | Core: the caller ends a turn after 1.2 s of agent quiet (energy, played out audio), or 0.6 s when a `transcript role=agent` arrived and the agent buffer is empty; the first caller turn waits 2.5 s for a greeting. Latency uses Silero onsets refined backward with energy (Silero reacts 30 to 90 ms late on soft onsets like "s") | Contract section 5 leaves end of turn open. The onset refinement keeps the latency metric from being biased high. |
| 2026-11-18 | Core: noise (`audio.noise`) is mixed into the caller utterances only; silence frames stay zero | Section 5 says silence is zero frames. A continuous noise bed is a later option. |
| 2026-11-18 | Core: the claude-cli provider runs `claude -p --model M --output-format json --system-prompt-file F --tools "" --setting-sources "" --strict-mcp-config --safe-mode --no-session-persistence`, prompt on stdin, cwd a temp folder | `--safe-mode` keeps the user's CLAUDE.md, hooks and plugins out (auth still works; `--bare` would drop OAuth). The system prompt goes through a file because argv is cut at the first newline on Windows. |
| 2026-11-18 | The planted demo bug lives only in the system prompt (book without reading day and time back); `--no-bug` or `ACME_BUG=0` turns it off | The first run shows a real judge failure; the fix is one flag. An LLM does not follow a prompt every time, so `--no-bug` can still fail sometimes; scenarios use `runs` and the pass rate for that. |
| 2026-11-18 | API: suite `status` is `running`, `finished` (the runner's `done`), `error` (the suite thread crashed) or `interrupted` (sqlite says running but no thread runs it, for example after a server restart). One suite at a time: a second POST gets 409 | The panel only tests `status === "running"`, so every other value reads as finished; `interrupted` stops a poll that would never end. |
| 2026-11-18 | API extra fields (additive): scenario list and detail add `valid`, `errors`; fixture list is objects `{id, description, file, tools, valid}`, detail `json` is an object; health adds `details`; `/api/runs` also takes `suite_id`; POST `/api/suites` also takes `runs`; extra `GET /api/runs/{id}/transcript`; Panchito adds `errors` per invalid proposal plus `llm_calls`, `elapsed_ms`, and `error` on timeout | The panel ignores unknown keys; the extras help the editor and debugging. |
| 2026-11-18 | Health probes run in parallel with 0.5 to 0.6 s timeouts and a 3 s cache; `stt` means faster-whisper is importable (find_spec, no import); `llm` never calls the model (claude-cli: `claude` on PATH; anthropic: key in env; ollama: model pulled). `localhost` is probed as `127.0.0.1` | The panel falls back to demo data when `/api/health` takes over 1.5 s. |
| 2026-11-18 | Onboarding: a detected step is stored, so it stays done; `viewed_report` is marked by `GET /api/runs/{id}`; `scenario_created` by a successful PUT of a scenario | A checklist that un-checks itself when the demo stops is confusing. The panel cannot tell the server it opened a report without an extra call. |
| 2026-11-18 | Stats: `latency_p50_7d` is the median of the per-run p50 values of the last 7 days, `latency_p95_7d` the nearest rank 95th of the per-run p95 values; `pass_rate_7d` excludes errors | Section 7 names the fields but not the math. Per-turn data is not in sqlite. |
| 2026-11-18 | Panchito: a new provider per request (so `max_calls_per_run` caps one request); 120 s total with a friendly reply; a proposed scenario whose fixture is proposed in the same answer skips the "fixture not found" check; a reply that is not JSON is shown as plain text | Matches the brief; proposals are never written by the server. |
| 2026-11-18 | `pv serve` binds `127.0.0.1` and `--open` opens `http://127.0.0.1:8700` (`/onboarding/` when the db has no runs); the server mounts the mock router at `/mock` and passes `http://127.0.0.1:<port>/mock` to the runner | Same reason as the mock url row: `localhost` can cost about 2 s per request on Windows. |
| 2026-11-18 | `pv init --yes` and `--answers` never start processes (demo, smoke test, panel) unless the answers file asks for them; an existing `panchovoice.yaml` is kept unless `overwrite` is true; the `acme-demo` agent is always kept so the demo scenarios stay valid | Safe in scripts and CI; the interactive wizard offers these actions with Yes as the Enter default. |
| 2026-11-18 | `pv init` writes `panchovoice.yaml` at the project root: `--config PATH`, else the cwd with `--here`, else the nearest folder with `scenarios/`, else the source checkout root when run inside it, else the cwd. Demo files are copied only into empty `scenarios/` and `fixtures/` of that root. The smoke test runs `book-happy-path` and `confirm-before-booking`; when `web/out` is missing and npm is on PATH the wizard offers `npm install` and `npm run build` in web/ | Running `pv init` from core/ must not create core/scenarios. `confirm-before-booking` holds the judge check that the planted bug fails, so the first suite fails on purpose. |
| 2026-11-18 | MCP: `pv mcp` is a stdio server on the official `mcp` SDK (v2, `MCPServer`) with 10 tools; it writes files only through `save_scenario` with `confirm=true` (without it the reply is a preview with a diff); `run_suite` reuses `SuiteManager` (one suite at a time), refuses when another process ran a suite step in the last 10 minutes, and starts its own mock tools server on a free port; expected failures are `ToolError` so the client reads the message | Confirm before change keeps a coding agent from editing tests behind the user's back. A free mock port avoids a clash with `pv serve` on 8700. The SDK hides the message of any other exception. |
| 2026-11-18 | `pv demo` passes `--stt-model base` unless the user passes `--stt-model` or sets `ACME_STT_MODEL`; the demo agent's own default stays `small` | Measured 2.0 s p50 with base vs 4.1 s with small, so the first run fails only on the planted bug. |
| 2026-11-18 | Core: `http-turn` adapter for agents that work one turn at a time over HTTP (optional transcribe, chat, optional speak). Agent config adds an `http` section; `url` is optional for http-turn and defaults to `http.base_url`. Secrets only through env var names (`auth: {type: bearer|cookie|header, env: NAME}`). The timeline is built, not paced: agent audio starts at caller end + wall clock of transcribe + chat + speak first byte; per turn rows add `stt_ms`, `llm_ms`, `tts_ms`, `pipeline_ms`. Mock server times are mapped onto that timeline. Requests carry `X-PV-Session` and `X-PV-Mock-Tools-Url`. `tools_from: actions` maps actions to tool calls (`source: actions`). Barge-in checks are `error` ("not supported by http-turn"); without transcribe, `wer_max` is `error`. mp3 decoded with `miniaudio` (MIT), a new core dependency | Many in-house assistants are not live calls. A built timeline keeps the stereo recording, latency and checks the same as the WebSocket adapter while a run takes only as long as the agent needs; `miniaudio` avoids a system ffmpeg. |
